ПОДГОТОВКА ГЕОМЕТРИЧЕСКОЙ МОДЕЛИ АВТОМОБИЛЯ ДЛЯ ПОСТРОЕНИЯ РАСЧЁТНОЙ СЕТКИ

1. ИСХОДНЫЕ ДАННЫЕ И ДИАГНОСТИКА

В качестве исходной геометрии использовалась STL-модель пикапа Dodge Ram,
полученная из открытых источников. Модель была загружена в пакет MeshLab
2025.07 для первичного анализа.

Диагностика топологических характеристик показала неудовлетворительное
состояние исходной геометрии: модель состояла из 19 несвязных компонентов,
содержала 3158 non-manifold рёбер и 70 non-manifold вершин. Наличие
non-manifold элементов делало построение расчётной сетки невозможным.
Кроме того, исходная модель имела некорректный масштаб — габариты
составляли порядка 45×95×35 условных единиц вместо реальных размеров
автомобиля.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

2. МАСШТАБИРОВАНИЕ МОДЕЛИ (MeshLab)

На основании реальных габаритов Dodge Ram (длина 5.8 м) был вычислен
коэффициент масштабирования: k = 5.8 / 95.25 ≈ 0.061. С помощью
инструмента Transform: Scale, Normalize модель была приведена к
метрическому масштабу. После масштабирования габариты составили
5.81 × 2.75 × 2.17 м, что соответствует реальным размерам автомобиля.

3. ОБЪЕДИНЕНИЕ КОМПОНЕНТОВ И УСТРАНЕНИЕ ПЕРЕСЕЧЕНИЙ (Blender)

Поскольку 19 компонентов модели геометрически пересекались друг с другом,
инструменты MeshLab не позволяли выполнить их корректное объединение.
Для решения этой задачи использовался пакет Blender.

После импорта STL-файла все компоненты были объединены в один объект
командой Join. Для обеспечения связности между колёсами и кузовом
(колёса не пересекали кузов, а лишь примыкали к нему) были добавлены
вспомогательные цилиндрические примитивы, имитирующие оси колёс.
Каждый цилиндр был расположен так, чтобы одновременно пересекать
и колесо, и кузов автомобиля.

Затем был применён инструмент Voxel Remesh с размером вокселя 0.02 м.
Данный метод перестраивает поверхность модели на основе воксельного
представления, автоматически устраняя все пересечения и формируя
единый замкнутый меш. Результатом стала геометрически корректная
модель, экспортированная в формате STL.

4. ФИНАЛЬНАЯ ОБРАБОТКА ГЕОМЕТРИИ (MeshLab)

Полученный после Voxel Remesh файл был загружен в MeshLab для
финальной обработки.

Диагностика показала значительное улучшение: модель стала двумерно
многообразной (two-manifold), число дыр равно нулю, число компонентов
сократилось до 4. Однако общее число полигонов составляло около
6 миллионов, что неприемлемо для последующего построения расчётной
сетки.

Для уменьшения числа полигонов был применён алгоритм Quadric Edge
Collapse Decimation с целевым числом граней 5000. Алгоритм
использует метод квадричных ошибок, что позволяет сохранить
геометрию модели при значительном уменьшении числа элементов.

Для устранения оставшихся артефактов и обеспечения гарантированной
замкнутости поверхности был применён инструмент Alpha Wrap, который
строит чистую внешнюю оболочку вокруг модели, игнорируя внутренние
дефекты геометрии.

После этого была выполнена переориентация нормалей (Re-Orient all
faces coherently) для обеспечения их единообразного направления
наружу от поверхности.

Финальная диагностика подтвердила корректность геометрии:
  — Число полигонов:       4988
  — Connected components:  1
  — Two-manifold:          да
  — Holes:                 0
  — Non-manifold edges:    0
  — Boundary edges:        0

5. ПОСТРОЕНИЕ РАСЧЁТНОЙ СЕТКИ (Gmsh)

Подготовленная STL-модель была загружена в библиотеку Gmsh 4.12
посредством C++ API. Построение сетки выполнялось в несколько этапов.

На первом этапе поверхность была классифицирована на логические патчи
с помощью метода classifySurfaces. Угол классификации был установлен
равным 80°, что обеспечивает грубое разбиение и минимальное число
поверхностей. Параметр forceParametrizablePatches был установлен в
true, что необходимо для корректной обработки сложной геометрии.

Вызов createGeometry() был намеренно исключён из pipeline, поскольку
для данной модели он приводил к ошибке параметризации вследствие
остаточных топологических дефектов.

Размер элементов сетки был задан равномерным полем MathEval со
значением 0.3 м. Для ускорения вычислений были задействованы все
доступные вычислительные потоки (8 потоков), оптимизация сетки
отключена.

Итоговая поверхностная сетка была построена командой generate(2)
и сохранена в формате MSH для дальнейшего использования в
вычислительном решателе.
